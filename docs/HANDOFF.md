# ¡Habla! — handoff

A structured Mexican-Spanish course for English speakers. Local-first Next.js web app; no backend, no AI calls.
Repo: https://github.com/evan-div/habla (`main`, last pushed commit `674cf60`).

## State of the project

**Working and verified**
- 24 playable units, 121 lessons, ~2,800 exercises (incl. teaching cards), 557 words, 64 grammar topics, 4 *Real Talk* (slang/vulgar) lessons.
- Core loop: onboarding → (optional placement) → lesson → feedback → XP/streak/achievements → mastery update → spaced review → progress charts.
- Pages: Home, Course, Vocabulary (+ word detail), Review (+ practice mode), Progress, Profile/Settings, Grammar reference, Onboarding, Placement.
- `npm run check` = `tsc --noEmit` + ESLint + Vitest (84 tests). `npm run build` passes (static routes for every unit/grammar topic).

**Not built (deliberate)**: AI tutoring, speech recognition, accounts/cloud sync, leaderboards.
**Sections 4–6** are built: "Telling Stories" (Units 13–15: preterite, imperfect, travel & culture), "Real Conversations" (Units 16–18: reflexive verbs, object pronouns, commands) "Beyond the Present" (Units 19–21: future, comparisons, conditional) and "Speaking With Nuance" (Units 22–24: progressive and present perfect, the subjunctive, prepositions and connectors). No units are stubbed on the map.

## Run it

```bash
npm install
npm run dev          # http://localhost:3000
npm run check        # run before every commit
```
Profile → *Testing tools*: **Load sample progress** (2 weeks of replayed sessions) and **+1 day / +1 week** time travel for spaced repetition. Progress lives in `localStorage` key `habla:learner:local-learner` (clear it to restart onboarding).

## Things worth knowing before you change anything

1. **Next.js 16 is not the Next you know.** `AGENTS.md` says to read `node_modules/next/dist/docs/` first. `params` is a Promise; route types are generated by `next dev/build` (so `LayoutProps` errors from bare `tsc` before a first build are harmless — I avoided those types).
2. **The content test is the quality gate** (`src/content/content.test.ts`). It fails if a word is tested before it's introduced, isn't practiced twice in its intro lesson and 3× overall, grammar is tested before it's taught, an exercise isn't answerable, a tile bank can't build an accepted sentence, or slang/vulgar words lack `regions`. When it fails, fix the content, not the test. Words introduced only via a "how people actually say it" card (`natural(...)` with vocab ids) are exempt from the repetition rule.
3. **Mastery is stored as `strength` and computed on read.** `masteryScore` on a word is only a snapshot; always use `masteryAt(word, now)` (selectors do). Scheduling advances **once per session per word**, not per answer.
4. **"Now" comes from the store**, honoring `clockOffsetMs` (dev time travel). Don't call `Date.now()` in render; use `useLearner()`/`useNow()`.
5. **Placement** marks earlier lessons `placedOut`, seeds their words at ~45% mastery spread over the next 6 days of review, and excludes them from lesson/unit achievements. Placed-out lessons pay full XP the first time they're actually played.
6. **Option order is shuffled at module load** (`lesson()` in builders, seeded by exercise id) — deterministic, so don't expect authored order.
7. **Typed-answer leniency:** accent-only slips and one-letter typos (answers ≥ 6 chars) count as correct with a note; `ñ` is treated as a distinct letter.
8. **React 19.2 specifics:** `useEffectEvent` is used for global key handlers (satisfies the `react-hooks/refs` lint rule). Refs aren't written during render.
9. **Running `next build` while `next dev` is up** floods the console with HMR websocket errors. Harmless; stop dev first.
10. `vitest.config.mts` is `.mts` on purpose (avoids a Vite CJS-config warning).
11. Lessons unlock in order. To test a late unit in the browser, take the placement check (a deliberate wrong answer at the unit you want puts you there). Lesson route is `/learn/<lessonId>`. Two content tests are worth knowing: every listed alternative answer must evaluate as correct, and the review generator must build answerable exercises for every word.
12. The `gh` CLI isn't installed on this machine; the repo remote was added by URL.

## Known gaps and risks

- **Spanish has not been reviewed by a native speaker.** All content (sentences, notes, pronunciation respellings, slang labels) was written by the assistant. This is the biggest quality risk — do this before any public launch.
- **Placement can be gamed/guessed** (3-option multiple choice, 2 questions per unit); a lucky guesser may start a unit or two high. Retake/"start from the beginning" mitigate it.
- **Leaving a lesson loses that lesson's progress** (no mid-lesson resume).
- **Audio is browser speech synthesis.** Quality varies by OS; macOS has good `es-MX` ("Paulina"). Voice picker prefers `es-MX` and avoids novelty voices. Recorded audio plugs in via `AudioRef.sources`.
- **No browser/E2E tests.** The core loop was verified manually in a browser pane and by `loop.test.ts`; phone/tablet layouts were checked in an emulator only (no real iOS/Android pass).
- **`npm audit`** reports 5 high advisories in the dev-tooling chain from the Next scaffold (not runtime code).
- Progress is per-browser; there's export/import in Profile as the only transfer mechanism.

## Suggested next steps (in rough priority)

1. Native-speaker content review (especially Real Talk lessons, Units 9–24).
2. Next content: Units 25+ — the roadmap has the past perfect, the imperfect subjunctive (si tuviera…) and impersonal/passive se (see `content/grammar/roadmap.ts`); also more Real Talk and longer reading/dialogue lessons. The course now covers the full set of core tenses, so a good next step is a review/"mixed practice" mode that draws on all of them. Past-tense forms are taught in grammar tables only (reflexive verbs store the pronoun in the present table, e.g. `me levanto`); `VerbData` still stores present tense only, so the word-detail conjugation table doesn't show preterite/imperfect yet.
3. Recorded audio for the highest-frequency words/phrases.
4. Resume-mid-lesson (persist `SessionState` per lesson).
5. Playwright tests for onboarding → lesson → review.
6. Deploy (e.g. Vercel) + CI running `npm run check`.
7. Accounts + sync behind `LearnerRepository` / `lib/auth/session.ts`.
8. Optional speaking exercises using the Web Speech recognition API.
